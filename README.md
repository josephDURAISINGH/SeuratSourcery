## Description

Single-Cell transcriptomic dataset can be extremely valuable for analyzing expression patterns across different samples, conditions, and organisms. However, since this data can be generated by different labs, technologies and sequencing methods, data gets messy fast. Preparing very different datasets for comparison is a logistical pain, so SeuratSourcery helps streamline the process and allows for easy compatability between these datasets, while cleanly showing the meta level characteristics of these datasets.

Just pass in a messy set of datasets and let the sourcery do its magic.

SeuratSourcery provides an easy to use workflow that allows for:

Loading in RNA-seq datasets in various forms Inspecting their structure Harmonizing gene names and assay formats Quality control summaries Meta level summaries

These cleaned Seurat objects can be used effectively in downstream analysis in Seurat functions (See <https://satijalab.org/seurat/articles/integration_introduction> for more info on this kind of experiment).

The `SeuratSourcery` package was developed using `R version 4.5.1 (2025-06-13)`, `Platform: aarch64-apple-darwin20` and `Running under: macOS Sequoia 15.5`.

SeuratSourcery is not designed to replace Seurat but rather prepare data for maximum effectiveness

# Core Functions

1.  ***summonData()*** Loads scRNA-seq files (RDS, h5Seurat, 10x) into a list of Seurat objects.

2.  ***runeInspection()*** Compares different metrics between the datasets such as gene overlap, metadata fields, qc summaries.

3.  ***getSourceryReport()*** Outputs graphs that represent these metrics such as gene/cell counts, UMIs, overlapping features.

4.  ***activateRune()*** Does various harmonization techniques such as making sure gene names are in compatible formats, that assays are compatible and that counts data is clean.

5.  ***performSourcery()*** a wrapper function that goes through the whole pipeline: loading input -\> inspection -\> harmonization -\> inspection -\> output.

6.  ***runSeuratSourcery()*** shiny app implementation.

Recommended to download your own data since it single cell data is too large to include here but can use ***demo_rune_data()*** to load in a small mock dataset

Pipeline

```         
            +-----------------------------+
            |     Input Datasets          |
            |  (.rds / .csv / .h5ad /     |
            |   .loom / 10X folders)      |
            +--------------+--------------+
                           |
                     summonData()
                           |
                           v
            +-----------------------------+
            | Pre-Harmonization QC        |
            | - runeInspection()          |
            | - getSourceryReport()       |
            +--------------+--------------+
                           |
                     activateRune()
                           |
                           v
            +-----------------------------+
            | Post-Harmonization QC       |
            | - runeInspection()          |
            | - getSourceryReport()       |
            +--------------+--------------+
                           |
                           v
            +-----------------------------+
            | Harmonized Seurat Objects   |
            | (ready for downstream use)  |
            +--------------+--------------+

                       (Optional)
                           |
                           v
        +---------------------------------------------+
        | Integration Analysis (Performed in Seurat)  |
        | SCTransform → FindIntegrationAnchors →      |
        | IntegrateData                               |
        +---------------------------------------------+

     performSourcery() runs this entire pipeline
```
